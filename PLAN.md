# Maintenance plan

GmapsXploit is maintained in small, focused commits. One change a day.

This is a working plan, not a contract.

## Week 1

- Mon - argument parsing and help
- Tue - version output
- Wed - color control
- Thu - detect missing curl
- Fri - smoke test
- Sat - continuous integration
- Sun - README pass

## Week 2

- Mon - add more Maps endpoints
- Tue - add more Cloud endpoints
- Wed - refine restriction detection
- Thu - report template pass
- Fri - example report refresh
- Sat - exit code table
- Sun - docs pass

## Week 3

- Mon - quiet mode pass
- Tue - timeout handling pass
- Wed - batch keys from a file
- Thu - JSON output option
- Fri - detection notes pass
- Sat - references pass
- Sun - README pass

## Week 4

- Mon - release checklist
- Tue - tag the release
- Wed - announce
- Thu - final review
- Fri - sources check
- Sat - plan the next item
- Sun - rest

## Commit conventions

- one change per commit, present tense
- subject under 72 characters, no trailing period
- run the checks before committing

## Daily checklist

1. Pick the next item.
2. Make the smallest change that completes it.
3. Run the checks.
4. Commit with a plain message.
5. Push to main.
